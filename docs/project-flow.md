## 二、用户认证流程

### 2.1 用户注册

```
前端: 用户填写注册表单 → 点击注册按钮
       │
       ▼
     POST /api/auth/register
       │
后端: 验证用户名是否已存在
       │
       ├── 已存在 → 返回错误信息
       │
       └── 不存在 → 加密密码 → 创建用户 → 返回用户信息
```

| 步骤 | 前端操作 | 后端处理 | 关键接口 |
| :--- | :--- | :--- | :--- |
| 1 | 填写用户名、密码、昵称 | - | - |
| 2 | 调用注册API | 验证用户名唯一性 | `POST /api/auth/register` |
| 3 | 接收响应 | 加密密码并创建用户 | 返回 `UserResponseDTO` |
| 4 | 自动登录或跳转登录页 | - | - |

### 2.2 用户登录

```
前端: 用户填写登录表单 → 点击登录按钮
       │
       ▼
     POST /api/auth/login
       │
后端: 验证用户名和密码
       │
       ├── 验证失败 → 返回错误信息
       │
       └── 验证成功 → 生成JWT令牌 → 返回令牌和用户信息
```

| 步骤 | 前端操作 | 后端处理 | 关键接口 |
| :--- | :--- | :--- | :--- |
| 1 | 填写用户名、密码 | - | - |
| 2 | 调用登录API | 验证用户凭据 | `POST /api/auth/login` |
| 3 | 接收响应 | 生成accessToken和refreshToken | 返回 `TokenResponseDTO` |
| 4 | 存储令牌到localStorage | - | - |
| 5 | 设置Token自动刷新定时器 | - | - |
| 6 | 跳转首页 | - | - |

### 2.3 Token刷新

```
前端: 每45分钟自动调用刷新API
       │
       ▼
     POST /api/auth/refresh
       │
后端: 验证refreshToken
       │
       ├── 验证失败 → 返回401，前端跳转登录页
       │
       └── 验证成功 → 生成新令牌 → 返回新令牌
```

## 三、游戏模式详解

### 3.1 无尽适应模式 (Endless Mode)

**核心特点**: 动态难度调节 + 遗传进化算法，无限回合，持续挑战

#### 3.1.1 游戏流程

| 阶段 | 流程描述 | 关键操作 |
| :--- | :--- | :--- |
| 准备阶段 | 用户选择字符类型（字母/数字/符号） | 选择训练范围 |
| 开始阶段 | 调用 `getNextRound` 获取首轮配置 | 初始难度计算 |
| 进行阶段 | 用户输入消灭怪物，每轮结束获取下一轮配置 | 遗传算法生成内容 |
| 结算阶段 | 游戏结束，上传记录，更新统计 | 难度系数更新 |

#### 3.1.2 核心机制

```
┌─────────────────────────────────────────────────────────┐
│                  无尽适应模式核心机制                    │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  用户表现（准确率、速度）                                 │
│         │                                               │
│         ▼                                               │
│  数学模型计算难度系数(Dt)                                 │
│         │                                               │
│         ├── 难度提升 → 怪物速度加快、数量增多、字符串变长 │
│         │                                               │
│         └── 难度降低 → 怪物速度减慢、数量减少、字符串变短 │
│                                                         │
│  遗传算法生成下一轮内容                                   │
│         │                                               │
│         ├── 选择父本（错误多、存活久的怪物）               │
│         │                                               │
│         ├── 基因重组（交叉生成新字符串）                   │
│         │                                               │
│         └── 变异（易错字符加权变异）                       │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

#### 3.1.3 关键接口调用

| 阶段 | 接口 | 说明 |
| :--- | :--- | :--- |
| 开始游戏 | `POST /api/game/config/next-round` | 获取首轮配置（roundNum=1） |
| 每轮结束 | `POST /api/game/config/next-round` | 获取下一轮配置（携带当前难度） |
| 游戏结束 | `POST /api/game/records` | 保存游戏记录 |
| 更新统计 | `POST /api/stats/character` | 更新字符统计 |

### 3.2 词源界定模式 (Dictionary Mode)

**核心特点**: 使用预设词库内容，针对性训练特定词汇

#### 3.2.1 游戏流程

| 阶段 | 流程描述 | 关键操作 |
| :--- | :--- | :--- |
| 词库选择 | 用户选择系统词库或自定义词库 | 支持多选词库 |
| 开始阶段 | 调用 `getNextRound` 获取首轮配置 | 从词库中提取单词 |
| 进行阶段 | 用户输入消灭怪物，使用词库内容 | 固定词库，难度递增 |
| 结算阶段 | 游戏结束，上传记录，更新统计 | 统计词库单词掌握情况 |

#### 3.2.2 词库选择界面

| 词库类型 | 说明 | 示例 |
| :--- | :--- | :--- |
| 系统词库 | 内置词库，不可修改 | 英语四级词汇、编程常用词汇 |
| 自定义词库 | 用户自建词库 | 专业术语、个人易错词汇 |

#### 3.2.3 关键接口调用

| 阶段 | 接口 | 说明 |
| :--- | :--- | :--- |
| 获取系统词库 | `GET /api/dictionary/system` | 获取系统词库列表 |
| 获取自定义词库 | `GET /api/dictionary/custom/user/{userId}` | 获取用户自定义词库 |
| 创建自定义词库 | `POST /api/dictionary/custom` | 创建新的自定义词库 |
| 开始游戏 | `POST /api/game/config/next-round` | 获取首轮配置（携带词库ID） |
| 游戏结束 | `POST /api/game/records` | 保存游戏记录 |

### 3.3 限时冲刺模式 (Limit Mode)

**核心特点**: 固定时间内尽可能多地消灭怪物，追求高分

#### 3.3.1 游戏流程

| 阶段 | 流程描述 | 关键操作 |
| :--- | :--- | :--- |
| 准备阶段 | 用户选择时间长度（1分钟/3分钟/5分钟） | 设置倒计时时间 |
| 开始阶段 | 调用 `getNextRound` 获取首轮配置 | 初始难度计算 |
| 进行阶段 | 用户输入消灭怪物，倒计时结束后游戏终止 | 时间紧迫，追求速度 |
| 结算阶段 | 游戏结束，上传记录，更新统计 | 根据分数排名 |

#### 3.3.2 时间选项

| 时间选项 | 说明 | 适用场景 |
| :--- | :--- | :--- |
| 1分钟 | 短时间冲刺 | 快速练习 |
| 3分钟 | 标准时长 | 日常训练 |
| 5分钟 | 长时间挑战 | 耐力训练 |

#### 3.3.3 关键接口调用

| 阶段 | 接口 | 说明 |
| :--- | :--- | :--- |
| 开始游戏 | `POST /api/game/config/next-round` | 获取首轮配置 |
| 每轮结束 | `POST /api/game/config/next-round` | 获取下一轮配置 |
| 游戏结束 | `POST /api/game/records` | 保存游戏记录 |
| 获取排行榜 | `GET /api/leaderboard/limit` | 获取限时模式排行榜 |

## 四、游戏核心流程

### 4.1 游戏准备阶段

```
前端流程：
1. 用户进入准备页
2. 选择游戏模式
   - 无尽适应模式：选择字符类型（字母/数字/符号）
   - 词源界定模式：选择词库
   - 限时冲刺模式：选择时间长度
3. 点击「开始游戏」按钮
4. 调用 getNextRound API
5. 获取到配置后初始化游戏引擎

后端流程：
1. 接收 getNextRound 请求
2. 根据用户ID查询历史数据（字符统计、游戏记录）
3. 计算初始难度系数
4. 生成首轮怪物列表
5. 返回配置参数和怪物数据
```

### 4.2 游戏进行阶段

```
前端流程：
1. 显示怪物列表，等待用户输入
2. 监听键盘输入事件
3. 匹配输入的字符串与怪物目标字符串
4. 匹配成功：消灭怪物，增加分数
5. 匹配失败：错误计数，怪物加速
6. 每消灭一波怪物后，调用 getNextRound 获取下一轮配置
7. 更新游戏状态和统计数据

后端流程：
1. 接收 getNextRound 请求
2. 使用数学模型计算当前难度系数
3. 使用遗传算法生成下一轮内容：
   - 选择父本（根据错误次数和存活时间）
   - 基因重组（交叉生成新字符串）
   - 变异（易错字符加权）
4. 根据难度系数调整：
   - 怪物速度
   - 怪物数量
   - 字符串长度
   - 怪物类型占比
5. 返回新的配置参数和怪物数据
```

### 4.3 游戏结束阶段

```
前端流程：
1. 游戏结束条件触发：
   - 无尽适应模式：怪物到达终点或用户主动退出
   - 词源界定模式：词库内容用完或用户主动退出
   - 限时冲刺模式：倒计时结束
2. 收集游戏数据：
   - 游戏记录（分数、速度、准确率等）
   - 怪物历史记录（每个怪物的输入统计）
   - 字符统计（按字符展开）
3. 调用 createGameRecord API 上传游戏记录
4. 调用 updateStats API 更新字符统计
5. 显示游戏结果页面

后端流程：
1. 接收游戏记录数据
2. 保存游戏记录和怪物数据
3. 更新用户统计信息
4. 更新字符统计信息
5. 在无尽适应模式下：
   - 使用遗传算法选择父本
   - 更新难度系数
6. 返回结算摘要
```

## 五、怪物类型与行为

### 5.1 怪物类型说明

| 类型 | 标识 | 行为特点 | 难度等级 |
| :--- | :--- | :--- | :--- |
| 普通怪物 | NORMAL | 匀速移动，无特殊能力 | 低 |
| 攻击型怪物 | ATTACKER | 移动速度快，到达终点造成伤害 | 中 |
| 闪避型怪物 | EVASIVE | 随机改变移动方向，难以瞄准 | 中 |
| 智能怪物 | SMART | 根据用户输入速度动态调整自身速度 | 高 |

### 5.2 怪物类型占比随难度变化

| 难度等级 | NORMAL | ATTACKER | EVASIVE | SMART |
| :--- | :--- | :--- | :--- | :--- |
| 1-3 | 70% | 15% | 10% | 5% |
| 4-6 | 50% | 25% | 15% | 10% |
| 7-10 | 30% | 30% | 25% | 15% |

## 六、数据统计与分析

### 6.1 游戏结束统计

| 统计项 | 说明 | 计算方式 |
| :--- | :--- | :--- |
| 总分 | 游戏总得分 | 各怪物得分之和 |
| 总字符数 | 输入的总字符数 | 所有怪物目标字符串长度之和 |
| 正确字符数 | 正确输入的字符数 | 总字符数 - 错误字符数 |
| 平均速度 | 平均输入速度 | 总字符数 / 游戏时长 × 60 (cpm) |
| 峰值速度 | 最高输入速度 | 单轮最快速度 |
| 平均准确率 | 平均准确率 | 正确字符数 / 总字符数 × 100% |
| 峰值准确率 | 最高准确率 | 单轮最高准确率 |

### 6.2 字符统计更新

游戏结束后，前端将每轮输入按字符展开，调用 `POST /api/stats/character` 更新字符统计：

| 字段 | 说明 |
| :--- | :--- |
| charValue | 字符值 |
| totalInput | 输入次数 |
| errorCount | 错误次数 |
| correctCount | 正确次数 |

## 十一、关键业务场景

### 11.1 新用户首次游戏

```
1. 用户注册并登录
2. 选择游戏模式（如无尽适应模式）
3. 系统根据默认初始难度生成首轮怪物
4. 用户开始游戏，系统记录表现数据
5. 游戏结束，更新用户统计和字符统计
6. 后续游戏根据历史数据动态调整难度
```

### 11.2 老用户回归游戏

```
1. 用户登录
2. 系统读取用户历史数据（字符统计、游戏记录）
3. 根据历史数据计算初始难度（基于上次游戏难度）
4. 用户开始游戏，难度从上次水平继续
5. 系统根据当前表现调整难度
```

### 11.3 易错字符专项训练

```
1. 用户查看字符统计，发现易错字符
2. 选择词源界定模式，创建包含易错字符的自定义词库
3. 开始游戏，针对性练习易错字符
4. 游戏结束，字符统计更新
5. 反复练习，直到易错字符准确率提升
```

## 十二、流程优化建议

| 优化点 | 说明 | 收益 |
| :--- | :--- | :--- |
| 预加载词库 | 游戏开始前预加载词库内容 | 减少游戏中的API调用延迟 |
| 本地缓存统计 | 游戏过程中本地缓存统计数据 | 减少实时更新压力 |
| 批量上传记录 | 游戏结束后一次性上传所有数据 | 减少网络请求次数 |
| WebSocket推送 | 使用WebSocket推送游戏状态 | 实时同步，提升用户体验 |
